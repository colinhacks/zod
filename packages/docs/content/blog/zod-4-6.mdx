Zod 4.6 is now available.

```sh
npm install zod@latest
```

At a glance:

- [`z.properties()`](#zproperties) — now a schema that infers, with a `.properties()` method on `z.instanceof()`
- [`@zod/mini`](#zodmini) — Zod Mini, published as its own package
- [Faster failures](#faster-failures) — up to 4.7x on the failure path when you only check `success`
- [Less memory per schema](#less-memory-per-schema) — up to 17% on top of the 9x reduction in Zod 4.5
- [Recursive schemas built by a factory](#recursive-schemas-built-by-a-factory) no longer crash

## `z.properties()`

Zod 4.5 shipped `z.properties()` as an array of checks, which meant it could assert but never narrow. It is now a schema, so it infers. ([#6536](https://github.com/colinhacks/zod/pull/6536))

```ts
const httpsUrl = z.instanceof(URL).properties({
  protocol: z.literal("https:"),
  hostname: z.string().regex(z.regexes.domain),
});

type HttpsUrl = z.infer<typeof httpsUrl>;
// URL & { protocol: "https:"; hostname: string }
```

The named properties are asserted in place and the input comes back untouched, so prototypes, unlisted keys, and object identity all survive. Every failing property is reported, not just the first.

```ts
httpsUrl.parse(new URL("https://example.com"));  // ✅ the same URL instance
httpsUrl.parse(new URL("http://nope"));          // ❌ protocol, hostname
```

The 4.5 spread form still compiles and runs, because the schema yields itself from `Symbol.iterator`.

```ts
z.instanceof(URL).check(...z.properties({ protocol: z.literal("https:") })); // ✅
```

<Callout>Spreading `z.properties()` now yields one element instead of one per key. Code that destructured or mapped that array sees a different shape; `.check(...)` and the new method form are unaffected.</Callout>

## `@zod/mini`

Zod Mini is now published as a standalone package. It re-exports `zod/mini` from a peer dependency on `zod`, and its version tracks `zod` release for release. ([#6491](https://github.com/colinhacks/zod/pull/6491))

```sh
npm install @zod/mini zod
```

```ts
import * as z from "@zod/mini";
```

The `zod/mini` subpath is unchanged and is not going anywhere. The standalone package exists for tooling that resolves bare package names rather than subpaths, and it bundles to the same bytes.

## Faster failures

Zod 4.5 made failing parses about 7.5x faster by skipping the stack trace. Zod 4.6 takes the next piece: `safeParse()` no longer finalizes issues or constructs the `ZodError` until something actually reads `result.error`. A caller that only branches on `success` never pays for either. ([#6519](https://github.com/colinhacks/zod/pull/6519), [#6509](https://github.com/colinhacks/zod/pull/6509))

```ts
const result = Player.safeParse({ username: 42, bio: "hello", xp: "12" });
result.success; // false — 1.10µs in 4.5, 236ns in 4.6
```

Reading the error costs what it always did, plus a little: the same work now happens behind an accessor, which measures about 1.4x slower than building it eagerly. The trade favors the overwhelmingly common case, where a failing parse is counted, logged by code, or turned into a boolean.

The Standard Schema surface got the same treatment from the other direction. A failing `~standard.validate` reports its issues straight off the raw payload and never builds a `ZodError` at all.

## Less memory per schema

Zod 4.5 cut retained heap per schema by up to 9x. Zod 4.6 takes another 5–17% off the container types, by moving the internal memo box's accessor onto a prototype instead of allocating it per instance. ([#6537](https://github.com/colinhacks/zod/pull/6537), [#6540](https://github.com/colinhacks/zod/pull/6540), [#6531](https://github.com/colinhacks/zod/pull/6531))

| schema | 4.5 | 4.6 |
| --- | --- | --- |
| `z.object({})` | 3176 b | 2648 b |
| `z.discriminatedUnion()`, 2 options | 12705 b | 11056 b |
| `z.object()`, 3 keys | 5278 b | 4746 b |
| `z.object()`, 10 keys | 11160 b | 10633 b |
| `z.enum(['a','b','c'])` | 1531 b | 1432 b |
| `z.literal('a')` | 1730 b | 1640 b |
| `z.object()`, 3 keys, `zod/mini` | 3736 b | 3480 b |

Literal and enum schemas also build their pattern regex lazily now, which is what accounts for their share. Construction got cheaper along with it.

## Recursive schemas built by a factory

A recursive schema built by a factory function threw `RangeError: Maximum call stack size exceeded` on Zod 4.5, after roughly eight seconds on the main thread. It parses again. ([#6530](https://github.com/colinhacks/zod/pull/6530))

```ts
const Node = (): any =>
  z.object({
    id: z.number(),
    get child() {
      return z.array(Node()); // a fresh instance on every read
    },
  });

z.object({ root: Node() }).parse({ root: { id: 1, child: [] } }); // ✅
```

Published schemas hit this — `zod-geojson` builds its geometry schemas this way, so an empty feature collection crashed. Closes [#6526](https://github.com/colinhacks/zod/issues/6526).

## Bug fixes

### ⚠️ Error maps run on the first read of `error`

Because `safeParse()` now builds its error lazily, a global error map, a locale, and a per-schema `error` function all run when `result.error` is first read rather than when the parse happens. Code that swaps `z.config()` between the parse and the read gets the newer configuration. ([#6519](https://github.com/colinhacks/zod/pull/6519))

```ts
const result = schema.safeParse(12);
z.config(z.locales.fr());
result.error.issues[0].message; // French in 4.6, English in 4.5
```

An error map with a side effect never runs at all if nothing reads the error. `.parse()` is unaffected, since it reads the error to throw it.

### ⚠️ `z.emoji()` rejects component-only strings

The emoji class covers the pieces that combine with an emoji, not emoji themselves, so `z.emoji()` accepted `"123"`, `"#"`, `"*"`, and a lone zero-width joiner, variation selector, or skin tone modifier. A leading lookahead now requires at least one real anchor. ([#6532](https://github.com/colinhacks/zod/pull/6532))

```ts
z.emoji().parse("😀");   // ✅
z.emoji().parse("1️⃣");   // ✅ the keycap is the anchor
z.emoji().parse("123");  // ❌ was accepted in 4.5
```

Flags, subdivision flags, skin-tone-modified emoji, and ZWJ sequences are unchanged. Closes [#6515](https://github.com/colinhacks/zod/issues/6515).

### ⚠️ `fromJSONSchema()` enforces six keywords it used to drop

Six validation keywords were listed as recognized and then silently ignored: `minProperties`, `maxProperties`, `uniqueItems`, `contains`, `minContains`, and `maxContains`. A converted schema accepted data the source schema rejects, which is the worst failure mode for a validating converter. ([#6535](https://github.com/colinhacks/zod/pull/6535))

```ts
z.fromJSONSchema({ type: "object", minProperties: 1 }).safeParse({});
// 4.5: accepted — 4.6: rejected
```

### ⚠️ A numeric enum's reverse mappings are out of `.options`

A TypeScript enum carries both directions of its mapping at runtime. The parser already dropped the reverse half, but `.options` was read straight off the entries object, so a three-member numeric enum listed six values — three of which the schema rejects. ([#6542](https://github.com/colinhacks/zod/pull/6542))

```ts
enum Country { UK, Germany, France }

z.enum(Country).options; // 4.5: ["UK", "Germany", "France", 0, 1, 2] — 4.6: [0, 1, 2]
```

### ⚠️ base64 patterns

The runtime patterns for `z.base64()` and `z.base64url()` are the character sets, with length and padding enforced in code, so a multi-megabyte string can no longer overflow the regex stack through a composed schema. The JSON Schema output still emits the exact block forms, so `z.toJSONSchema()` is unchanged. ([#6534](https://github.com/colinhacks/zod/pull/6534), [#6527](https://github.com/colinhacks/zod/pull/6527))

Two consequences. Composing `z.base64()` into a template literal now checks the alphabet but not the length, matching how `z.creditCard()` already behaves there. And `z.regexes.base64url`, which is exported, is now the length-aware form and will overflow on a multi-megabyte input, exactly as `z.regexes.base64` always has.
