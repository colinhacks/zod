title: Zod JSON

Zod JSON is a variant of Zod whose schemas are JSON Schema. A schema's enumerable properties are its JSON Schema keywords, and the API is the API of [Zod Mini](/packages/mini).

```sh
npm install zod @zod/json
```

```ts
import * as z from "@zod/json";

const User = z.object({
  name: z.string().check(z.minLength(1)),
  age: z.optional(z.integer().check(z.minimum(0))),
  email: z.optional(z.email()),
});

type User = z.infer<typeof User>;
// => { name: string; age?: number; email?: string }

User.parse({ name: "Ada", age: 36 }); // ✅
User.parse({ name: "", age: 36 }); // ❌ minLength
```

The schema is the document. Its own properties are JSON Schema keywords and nothing else.

```ts
User.type; // "object"
User.required; // ["name"]
User.properties.age; // { type: "integer", minimum: 0 }

JSON.stringify(User, null, 2);
```

```json
{
  "type": "object",
  "properties": {
    "name": { "type": "string", "minLength": 1 },
    "age": { "type": "integer", "minimum": 0 },
    "email": { "type": "string", "format": "email" }
  },
  "required": ["name"]
}
```

Three rules shape the package:

- **The schema is the document.** Parsing methods and Zod internals are non-enumerable, so `JSON.stringify()`, spread, and `Object.keys()` see a plain JSON Schema. Nested schemas are nested documents.
- **Zod Mini's API.** Functions instead of methods, wrappers such as `z.optional()`, and constraints through `.check()`. Each check writes one keyword onto the schema.
- **Nothing is unrepresentable.** Every builder and check has a JSON Schema keyword. There are no dates, bigints, maps, transforms, or refinements.

## Checks

Constraints go through `.check()`, as in Zod Mini. A check is named after the keyword it writes.

```ts
z.string().check(z.minLength(5), z.maxLength(10));
// => { type: "string", minLength: 5, maxLength: 10 }
```

Every check is type-safe, so TypeScript rejects `z.minItems()` on a string. The full list, by the type it applies to:

```ts
// strings
z.minLength(n);
z.maxLength(n);
z.pattern(regex); // a RegExp or a string; a RegExp writes its source
z.format(name); // any format; the ten formats below are validated, the rest are annotations

// numbers and integers
z.minimum(n);
z.maximum(n);
z.exclusiveMinimum(n);
z.exclusiveMaximum(n);
z.multipleOf(n);

// arrays
z.minItems(n);
z.maxItems(n);
z.uniqueItems();
z.contains(schema);
z.minContains(n);
z.maxContains(n);

// objects
z.minProperties(n);
z.maxProperties(n);
z.propertyNames(schema);
z.patternProperties({ [pattern]: schema });
z.dependentRequired({ [key]: [...keys] });
z.dependentSchemas({ [key]: schema });

// metadata, on any schema
z.meta({ title, description, examples, deprecated, readOnly, writeOnly, $comment, $id, ...anything });
z.describe(text);
```

## Strings

```ts
z.string(); // { type: "string" }
z.string().check(z.minLength(1), z.maxLength(255));
z.string().check(z.pattern(/^[a-z]+$/)); // { type: "string", pattern: "^[a-z]+$" }
```

Formats that Zod already validates are builders, and each one writes `format`.

```ts
z.email(); // { type: "string", format: "email" }
z.uuid(); // format: "uuid"
z.url(); // format: "uri"
z.hostname(); // format: "hostname"
z.ipv4(); // format: "ipv4"
z.ipv6(); // format: "ipv6"
z.iso.datetime(); // format: "date-time"
z.iso.date(); // format: "date"
z.iso.time(); // format: "time"
z.iso.duration(); // format: "duration"

z.base64(); // { type: "string", contentEncoding: "base64" }
```

Any other format is an annotation. It is written to the document and not checked, as the spec allows.

```ts
z.string().check(z.format("iri-reference")); // { type: "string", format: "iri-reference" }
```

## Numbers

Both builders infer `number`. Infinity and `NaN` are rejected, since they are not JSON numbers.

```ts
z.number(); // { type: "number" }
z.integer(); // { type: "integer" }, accepts 1 and 1.0, rejects 1.5

z.number().check(z.minimum(0), z.maximum(1));
z.number().check(z.exclusiveMinimum(0), z.exclusiveMaximum(1));
z.integer().check(z.multipleOf(5));
```

## Booleans and null

```ts
z.boolean(); // { type: "boolean" }
z.null(); // { type: "null" }
```

## Literals and enums

Both accept any JSON value and compare structurally. The `type` keyword is written when every value has the same JSON type.

```ts
z.const("admin"); // { type: "string", const: "admin" }
z.const({ version: 1 }); // { type: "object", const: { version: 1 } }

z.enum(["draft", "published"]); // { type: "string", enum: ["draft", "published"] }
z.enum([0, 1, null]); // { enum: [0, 1, null] }
```

## Objects

A key is listed in `required` unless it is optional or has a default. The document describes the input.

```ts
const User = z.object({
  id: z.uuid(),
  name: z.string(),
  nickname: z.optional(z.string()),
  role: z._default(z.string(), "user"),
});
// => {
//   type: "object",
//   properties: {
//     id: { type: "string", format: "uuid" },
//     name: { type: "string" },
//     nickname: { type: "string" },
//     role: { type: "string", default: "user" },
//   },
//   required: ["id", "name"],
// }

type User = z.infer<typeof User>;
// => { id: string; name: string; nickname?: string; role: string }
```

Unknown keys pass through, as in JSON Schema. The strict and catchall forms write `additionalProperties`.

```ts
z.object({ name: z.string() }); // unknown keys are allowed and kept
z.strictObject({ name: z.string() }); // additionalProperties: false
z.catchall(z.object({ name: z.string() }), z.number()); // additionalProperties: { type: "number" }
```

Records write `additionalProperties` and, for a constrained key, `propertyNames`.

```ts
z.record(z.string(), z.number());
// => { type: "object", additionalProperties: { type: "number" } }

z.record(z.string().check(z.pattern(/^x-/)), z.string());
// => { type: "object", propertyNames: { type: "string", pattern: "^x-" }, additionalProperties: { type: "string" } }
```

The object checks constrain keys and key counts. None of them change the inferred type.

```ts
z.object({ card: z.optional(z.string()), cvv: z.optional(z.string()) }).check(
  z.minProperties(1),
  z.maxProperties(10),
  z.propertyNames(z.string().check(z.pattern(/^[a-z]+$/))),
  z.dependentRequired({ card: ["cvv"] }), // cvv is required whenever card is present
  z.dependentSchemas({ card: z.object({ cvv: z.string().check(z.pattern(/^\d{3}$/)) }) }),
);
```

The object helpers from Zod Mini return new documents.

```ts
z.extend(User, { admin: z.boolean() });
z.pick(User, { id: true });
z.omit(User, { role: true });
z.partial(User); // every key optional; required is dropped
```

Recursive objects use a getter. The document has a cycle, so `z.toJSONSchema()` is what turns it into a `$ref`.

```ts
const Category = z.object({
  name: z.string(),
  get children() {
    return z.array(Category);
  },
});

z.toJSONSchema(Category);
// => {
//   type: "object",
//   properties: {
//     name: { type: "string" },
//     children: { type: "array", items: { $ref: "#" } },
//   },
//   required: ["name", "children"],
// }
```

## Arrays and tuples

```ts
z.array(z.string()); // { type: "array", items: { type: "string" } }
z.array(z.string()).check(z.minItems(1), z.maxItems(10));
z.array(z.integer()).check(z.uniqueItems()); // structural equality
z.array(z.integer()).check(z.contains(z.const(0)), z.minContains(1), z.maxContains(3));
```

Tuples write `prefixItems`. The `items` keyword is `false` unless a rest schema is given.

```ts
z.tuple([z.string(), z.integer()]);
// => { type: "array", prefixItems: [{ type: "string" }, { type: "integer" }], items: false }

z.tuple([z.string()], z.integer());
// => { type: "array", prefixItems: [{ type: "string" }], items: { type: "integer" } }
```

## Composition

The applicator keywords are functions.

```ts
z.anyOf([z.string(), z.integer()]); // { anyOf: [...] }, string | number
z.oneOf([z.string(), z.integer()]); // { oneOf: [...] }, exactly one must match
z.allOf([User, Timestamps]); // { allOf: [...] }, User & Timestamps
z.not(z.const(null)); // { not: { const: null } }, unknown
```

Nullability writes a `type` array when the inner schema is a bare type, and an `anyOf` otherwise.

```ts
z.nullable(z.string()); // { type: ["string", "null"] }
z.nullable(z.email()); // { anyOf: [{ type: "string", format: "email" }, { type: "null" }] }
z.nullish(z.string()); // nullable and optional
```

Conditionals take the `if` schema and its `then` and `else` branches. The output type is the union of the two branches, so a conditional usually sits inside an `allOf` next to the object it constrains.

```ts
const Shape = z.allOf([
  z.object({
    kind: z.enum(["circle", "rect"]),
    radius: z.optional(z.number()),
    width: z.optional(z.number()),
    height: z.optional(z.number()),
  }),
  z.if(z.object({ kind: z.const("circle") }), {
    then: z.object({ radius: z.number() }),
    else: z.object({ width: z.number(), height: z.number() }),
  }),
]);
```

The boolean schemas `true` and `false` are the empty schema and its negation.

```ts
z.any(); // {}
z.unknown(); // {}
z.never(); // { not: {} }
```

## Metadata

Annotation keywords are written by `z.meta()` and `z.describe()`. In Zod Mini these register the schema in `z.globalRegistry`; in Zod JSON they write onto the document.

```ts
z.string().check(
  z.meta({ title: "Display name", examples: ["ada"], deprecated: true }),
  z.describe("Shown on the profile page"),
);
// => {
//   type: "string",
//   title: "Display name",
//   examples: ["ada"],
//   deprecated: true,
//   description: "Shown on the profile page",
// }
```

Keys that Zod JSON does not know are written verbatim, which is how OpenAPI extensions travel.

```ts
z.string().check(z.meta({ "x-internal": true, example: "ada" }));
// => { type: "string", "x-internal": true, example: "ada" }
```

## Errors

The `error` parameter customizes the message, as in Zod Mini. It is not a keyword and does not appear in the document.

```ts
z.string({ error: "Expected a string" }).check(z.minLength(8, { error: "At least 8 characters" }));
```

Issues are the `$ZodIssue` objects every Zod package produces, so [error formatting](/error-formatting) and [locales](/error-customization#internationalization) work unchanged. Like Zod Mini, Zod JSON loads no locale by default.

```ts
import * as z from "@zod/json";

z.config(z.locales.en());
```

## `z.toJSONSchema()`

For a schema without cycles, `JSON.stringify()` is the conversion. The function exists for cycles, shared subschemas, and older drafts.

```ts
z.toJSONSchema(User); // the same document JSON.stringify() produces
z.toJSONSchema(Category); // the cycle becomes { $ref: "#" }
z.toJSONSchema(User, { reused: "ref" }); // a schema used twice becomes a $def
z.toJSONSchema(User, { cycles: "throw" });
z.toJSONSchema(User, { target: "draft-07" }); // exclusiveMinimum as a boolean, prefixItems as an items array, $defs as definitions
z.toJSONSchema(User, { target: "draft-04" });
z.toJSONSchema(User, { target: "openapi-3.0" }); // nullable instead of type: "null", no const or prefixItems
```

There is no `unrepresentable`, `io`, `override`, or `metadata` option. Nothing is unrepresentable, the document already describes the input, and metadata is on the schema.

An `$id` names the schema in `$defs` and in the `$ref` that points at it.

```ts
const Address = z.object({ city: z.string() }).check(z.meta({ $id: "Address" }));

z.toJSONSchema(z.object({ home: Address, work: Address }), { reused: "ref" });
// => {
//   type: "object",
//   properties: { home: { $ref: "#/$defs/Address" }, work: { $ref: "#/$defs/Address" } },
//   required: ["home", "work"],
//   $defs: { Address: { $id: "Address", type: "object", properties: { city: { type: "string" } }, required: ["city"] } },
// }
```

The Standard Schema interface exposes the document too.

```ts
User["~standard"].jsonSchema.input; // the schema itself
```

## `z.fromJSONSchema()`

A JSON Schema document becomes a Zod JSON schema. Pass it `as const` and the TypeScript type is inferred from the document.

```ts
const Point = z.fromJSONSchema({
  type: "object",
  properties: { x: { type: "number" }, y: { type: "number" } },
  required: ["x", "y"],
} as const);

type Point = z.infer<typeof Point>; // { x: number; y: number }
Point.parse({ x: 1, y: 2 });
```

Without `as const` the schema still parses, and the inferred type is `unknown`.

The reader resolves local references (`#` and `#/$defs/...`), reads `$schema` to normalize draft-04 and draft-07 spellings, and keeps unknown keywords. The result round-trips: `z.toJSONSchema(z.fromJSONSchema(doc))` deep-equals `doc` for any document Zod JSON can express. Documents using `unevaluatedProperties`, `unevaluatedItems`, `$dynamicRef`, or an external `$ref` throw.

## Interop with `zod`

A Zod JSON schema is a core schema, so it nests inside `zod` and `zod/mini` containers. Refinements and transforms belong to the outer schema, since JSON Schema cannot express them.

```ts
import * as z from "@zod/json";
import * as zod from "zod";

const Signup = zod
  .object({
    user: User, // a Zod JSON schema
    password: zod.string().min(8),
  })
  .refine((v) => v.password !== v.user.name, { error: "Password cannot be your name" });
```

The two packages differ where JSON Schema and Zod disagree on a default, and where a keyword has a different name.

| | `zod/mini` | `@zod/json` |
| --- | --- | --- |
| Unknown object keys | stripped | passed through; `z.strictObject()` rejects them |
| Defaulted key in the document | required | not required; the document describes the input |
| Default locale | `en` | none |
| Dates, bigints, maps, sets, `undefined` | schemas | not JSON, not available |
| Coercion, transforms, refinements | built in | in the enclosing `zod` schema |
| Metadata | `z.globalRegistry` | keywords on the schema |
| Literals | `z.literal()` | `z.const()` |
| Unions | `z.union()`, `z.xor()`, `z.intersection()` | `z.anyOf()`, `z.oneOf()`, `z.allOf()` |
| Integers | `z.int()` | `z.integer()` |
| Regex | `z.regex()` | `z.pattern()` |
| Number bounds | `z.gte()`, `z.gt()`, `z.lte()`, `z.lt()` | `z.minimum()`, `z.exclusiveMinimum()`, `z.maximum()`, `z.exclusiveMaximum()` |

## Keyword reference

Every keyword in JSON Schema 2020-12 and what writes it.

| Keyword | Written by | Runtime |
| --- | --- | --- |
| `type` | every builder | validated |
| `properties`, `required` | `z.object()`, `z.optional()`, `z._default()` | validated |
| `additionalProperties` | `z.strictObject()`, `z.catchall()`, `z.record()` | validated |
| `patternProperties`, `propertyNames`, `minProperties`, `maxProperties`, `dependentRequired`, `dependentSchemas` | the check of the same name | validated |
| `items`, `prefixItems` | `z.array()`, `z.tuple()` | validated |
| `minItems`, `maxItems`, `uniqueItems`, `contains`, `minContains`, `maxContains` | the check of the same name | validated |
| `minLength`, `maxLength`, `pattern` | the check of the same name | validated |
| `format` | the format builders, `z.format()` | validated for the ten formats above, otherwise an annotation |
| `contentEncoding` | `z.base64()` | validated |
| `contentMediaType`, `contentSchema` | `z.meta()` | annotation |
| `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf` | the check of the same name | validated |
| `const`, `enum` | `z.const()`, `z.enum()` | validated, structural equality |
| `anyOf`, `oneOf`, `allOf`, `not` | `z.anyOf()`, `z.oneOf()`, `z.allOf()`, `z.not()`, `z.nullable()` | validated |
| `if`, `then`, `else` | `z.if()` | validated |
| `default` | `z._default()` | applied when the value is `undefined` |
| `title`, `description`, `examples`, `deprecated`, `readOnly`, `writeOnly`, `$comment`, `$anchor` | `z.meta()`, `z.describe()` | annotation |
| `$id` | `z.meta()` | annotation; names the `$def` |
| `$ref`, `$defs`, `$schema` | `z.toJSONSchema()` | local references only |
| `unevaluatedProperties`, `unevaluatedItems`, `$dynamicRef`, `$dynamicAnchor`, `$vocabulary` | nothing | `z.fromJSONSchema()` throws |
| anything else | `z.meta()` | written verbatim |

## Open questions

This section is the workpiece and is deleted before the page ships. Each item names the choice the page makes and the alternative.

1. **Keyword names or Zod Mini names.** The page names builders and checks after the keyword they write: `z.const()`, `z.anyOf()`, `z.oneOf()`, `z.allOf()`, `z.integer()`, `z.pattern()`, `z.minimum()`. Zod Mini spells the same things `z.literal()`, `z.union()`, `z.xor()`, `z.intersection()`, `z.int()`, `z.regex()`, `z.gte()`. Keyword names make the document readable from the code; Mini names make the package a drop-in. Aliases are the third option.
2. **Unknown object keys.** The page passes them through, which is what JSON Schema validation does. Zod strips them, and a stripped output still conforms to the document.
3. **What `required` describes.** The page lists a defaulted key as not required, so the document describes the input. Zod's `z.toJSONSchema()` describes the output by default and lists it as required.
4. **Nullable shape.** A `type` array for a bare inner type and `anyOf` otherwise, matching Zod's emitter. Always writing `anyOf` is simpler and one line longer.
5. **Formats.** The page ships builders for the ten formats Zod validates plus `z.base64()`, and `z.format()` for annotation-only formats. Zod's other string formats (`cuid`, `ulid`, `nanoid`, `emoji`, `e164`, ...) have no JSON Schema format and are written as `pattern` by the classic emitter. They can ship as `pattern` builders or be left to `z.string().check(z.pattern(z.regexes.cuid))`.
6. **Discriminated unions.** No keyword exists. `z.anyOf()` and `z.oneOf()` cover the semantics and lose the discriminator fast path and the targeted error. A `z.discriminatedUnion()` that writes `anyOf` plus OpenAPI's `discriminator` is the middle ground.
7. **Unknown keywords through `z.meta()`.** Written verbatim, which OpenAPI's `x-` extensions need, and a misspelled keyword is accepted silently.
8. **Package shape.** A standalone `@zod/json` with a peer dependency on `zod`, like `@zod/mini`. Not decided: whether it is also a `zod/json` subpath, and whether the source lives in `packages/json` or `packages/zod/src/v4/json`.
9. **Out of scope for the first release.** Multi-document output from a registry, `z.compile()` support for the new schema types, and moving the classic `z.toJSONSchema()` emitter out of `zod`.
